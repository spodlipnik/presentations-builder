# Talk Builder — Initial Setup

Guide the user through configuring their personal Talk Builder environment. This runs once and creates persistent configuration that all other talk-builder skills reference.

The goal is to capture the user's personal presentation style so that every future talk feels like *theirs*, not like a generic template. Ask questions conversationally — this should feel like a brief creative consultation, not a form.

## Important

The assets path comes from the plugin's `userConfig` system — it's stored in `${user_config.assets_path}`. If the user hasn't configured it yet, Claude Code will have prompted them when they enabled the plugin. If the value is empty, ask them to set it via plugin settings or provide a path now.

## Steps

### 1. Verify assets directory path

Check `${user_config.assets_path}`. If it's set, confirm with the user: "Your assets folder is set to `[path]`. Is this correct, or would you like to change it?"

If not set, ask the user where they want to store their Talk Builder assets (config, example slides, fixed slides). Suggest examples like `~/Documents/talk-builder/` but let them choose any path. Then tell them to update the plugin setting with the chosen path.

### 2. Check dependencies first

Check system dependencies before investing time in style questions. Run these checks silently and only report problems:

**poppler-utils** (for PDF image extraction):
```bash
which pdftoppm && which pdfseparate
```

If missing, tell the user: `poppler: brew install poppler` — needed to extract figures from research papers.

**cairo** (for SVG→PNG conversion in `talk-assets`):
```bash
[ -f /opt/homebrew/lib/libcairo.2.dylib ] || [ -f /usr/local/lib/libcairo.2.dylib ] || [ -f /opt/local/lib/libcairo.2.dylib ]
```

If missing, tell the user: `cairo: brew install cairo` — needed by Python `cairosvg` to render charts and diagrams. Without it, `talk-assets` SVG → PNG conversion fails with `OSError: no library called "cairo-2"`.

LibreOffice and Node.js are no longer required by talk-builder itself (PPTX generation is delegated to the official document-skills:pptx skill, which manages its own deps).

### 3. Create directory structure

Create the chosen directory with subdirectories:

```
<chosen-path>/
├── config.yaml
├── example-slides/
└── fixed-slides/
```

### 4. Collect user preferences (one question at a time)

Ask these questions sequentially, one per message. Adapt your language to match the user's — if they write in Spanish, ask in Spanish.

**Note:** Fonts and colors are collected in step 4b (design_tokens) and stored directly in `config.yaml`.

**Question 1 — Language (ask this first, it determines the language for remaining questions):**
"What language do you usually present in?"
- English
- Spanish
- Other (specify)

**Question 2 — Complexity default:**
"When you give talks, what's your typical audience level? This helps calibrate how much jargon and technical depth to use by default:"
- **Basic** — general audience, minimal jargon, focus on concepts
- **Moderate** — professionals in related fields, some technical terms okay
- **Advanced** — specialists, cutting-edge terminology expected

### 4b. Collect design tokens (colors and fonts)

These will be applied to every chart, diagram, and slide generated by talk-builder. Ask sequentially:

**Q4b-1: Primary color**
"What's your primary brand color? (Hex code, e.g. #0B3D91 for navy. This is the dominant color in your slides — used for accents and key text emphasis.)"

**Q4b-2: Accent color**
"What's your accent color? (Used sparingly for highlights — section labels, callouts. Hex code, e.g. #E63946 for red.)"

**Q4b-3: Text color**
"Default body text color? (Defaults to #1A1A1A near-black.)"

**Q4b-4: Background color**
"Default slide background color? (Defaults to #FFFFFF white.)"

**Q4b-5: Muted color**
"Color for secondary text — captions, attributions, dates? (Defaults to #6C757D gray.)"

**Q4b-6: Heading font**
"Font for slide titles, headlines, and big numbers? (e.g. Avenir Heavy, Inter Bold, Helvetica Neue Bold. The font must be installed locally.)"

**Q4b-7: Body font**
"Font for body text and captions? (e.g. Avenir Book, Inter Regular.)"

### 5. Ask about example slides

"Do you have existing presentations that represent your style? If so, place your .pptx or .key files in: `<chosen-path>/example-slides/`"

If the user confirms they have placed files there, analyze them to understand their presentation style patterns. Use observations to inform narrative suggestions in future talks — note layout, density, and visual conventions you observe. No separate field for this is written to config.yaml.

### 6. Ask about fixed slides

"Do you have slides you reuse in every presentation (contact info, disclosures, acknowledgments)? If so, place them in: `<chosen-path>/fixed-slides/`"

### 7. Generate config.yaml

Write the config file at `<chosen-path>/config.yaml` with user preferences and design tokens:

```yaml
language: "<user-answer>"
narrative_style: "conversational"
complexity_default: "<user-answer>"

design_tokens:
  color:
    primary: "<Q4b-1 answer>"
    accent: "<Q4b-2 answer>"
    text: "<Q4b-3 answer>"
    background: "<Q4b-4 answer>"
    muted: "<Q4b-5 answer>"
  typography:
    heading_font: "<Q4b-6 answer>"
    body_font: "<Q4b-7 answer>"
```

**Important:** `config.yaml` is the single source of truth for both *who you are* (language, complexity, narrative style) and *what your slides look like* (design_tokens). It's read by:
- `talk-narrative` for language and narrative style preferences
- `talk-assets` for design_tokens when generating SVG charts/diagrams
- `talk-slides` for design_tokens when delegating to document-skills:pptx

### 8. Confirm completion

Show the user a summary of their configuration — the language, complexity level, narrative style, and design_tokens (primary/accent colors, heading/body fonts). Then suggest: "Configuración completa. Empezá una nueva presentación con `/talk-builder:talk`."

## Reconfiguration

If the user already has a config and runs `/talk-setup` again, read the existing config first and show them their current settings. Ask which sections they want to update. Do not overwrite unchanged sections.
